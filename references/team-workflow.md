# 多人协作四步操作手册

## 一、任务卡：统筹人操作

多人制作时建议使用，个人制作可跳过。任务卡不是为了提高单页设计质量，而是作为多人协作时唯一、可检查的范围与版本依据：

- 明确谁负责哪一部分，防止重复制作和责任空档；
- 固定章节顺序，避免各负责人按自己的理解重排；
- 把每个章节绑定到正确的原始材料，防止拿错、漏读或跨范围引用；
- 统一整份报告的受众和目的，避免有人做成经营汇报、有人做成项目说明；
- 统一 Skill 和母版版本，避免合并时字体、主题、页码和品牌元素不同；
- 给最终合并者提供逐章核对清单，便于发现缺页、重页和错序。

任务卡不决定页数、页面版式、图表类型或具体构图，也不要求填写 `sectionId`。如果所有参与人已经通过其他方式明确并共同确认了上述信息，可以不用任务卡；但需要人工承担同样的协调和核对工作。任务卡本质上是把口头约定变成一个轻量、稳定的协作合同。

复制以下 Prompt：

```text
请使用 $mint-report-creative-ppt，只生成简化协作任务卡 report.creative-task.json，不生成PPT或HTML。

根据我提供的汇报名称、受众、汇报目的、大纲、负责人和材料路径，完整保留大纲顺序与责任边界。任务卡统一使用 mint-report-creative-ppt 当前版本和 mint-ppt-16x9-template.pptx（mint-template-16x9/1）。

任务卡只记录：汇报名称、章节顺序、章节标题、负责人、该章节要回答的问题、来源文件。不要预设页数、版式、图表或sectionId。默认全部业务内容进入正文、禁止附录、使用PowerPoint自动页码，页面底部除自动页码外不增加非必要注释。

信息缺失或负责人不明确时只询问缺失项，不自行猜测。完成后用简短清单说明每人负责内容。

【汇报名称】...
【大纲与负责人】...
【材料路径】...
```

## 二、生成页面指导 Prompt：各材料撰写人操作

这一步建议在 Creative Skill 外完成，输出只有 Prompt，不制作PPT。撰写人检查业务事实、取舍和页面目标后再进入下一步。

```text
请完整阅读我负责章节的全部原始材料，先理解业务逻辑、管理问题和信息关系，再生成一份可直接交给PPT设计Agent执行的“逐页页面制作Prompt”。

现在只输出制作Prompt，不制作PPT，不解释分析过程，不联网补充材料之外的业务事实。

你的角色是“管理汇报设计导演”：需要替后续PPT设计Agent把每一页“讲什么、什么最重要、观众要看懂什么、建议怎么表达”想清楚，但不要锁死像素坐标或固定模板。

==================================================
一、基本原则
==================================================

1. 原始材料是唯一业务事实来源。保留所有重要且独有的数字、单位、时间、范围、条件、预测属性、风险、限制和业务关系，不得自行补充事实。

2. 事实完整不等于原文照搬。允许压缩、改写和重新组织成适合管理层阅读的PPT文案，但不得改变原意。避免Markdown、字段摘要、大量“关键词｜关键词”及不必要的中英混排。

3. 相关内容优先形成一个完整管理故事。只有在保证可读字号、事实完整和信息层级后确实放不下，才在自然业务边界续页；不要因为小标题、图表类型不同而机械分页。

4. 所有必须业务信息进入可见正文，不以备注或附录代替。重要条件、风险和口径就近放到对应内容旁。

5. 页面底部除PowerPoint自动页码字段外，默认不增加非必要的“说明、阅读边界、备注、关键背景、来源”等区域。

6. 如果提供了PPT母版，整体字体、主题色、标题体系、页码、品牌元素和基础视觉语言优先遵循母版。母版负责整体一致性，不限制每页主体构图。

==================================================
二、逐页制作指导
==================================================

每一页请按照以下结构输出：

【本页主题】
这一页解决什么管理问题。

【本页在章节中的作用】
说明为什么需要这一页。只有当本页与前后页存在真实的因果、递进、依赖、比较、总分或问题—应对关系时，才说明页面间关系；不要强行制造“承上启下”。

【5秒核心认知】
明确写：“管理层看这页5秒后，必须理解：______。”

【核心结论】
给出适合管理汇报的核心判断。如果属于基于材料的推导而非原文事实，要明确说明，不得把推导包装成原始事实。

【必须保留的业务事实与内容边界】
列出本页必须出现的数字、单位、时间、范围、条件、预测属性、风险、限制、对象及重要业务关系。同时指出哪些内容不应进入本页，以及材料未支持、不得自行扩展的内容。

【标题与展示文案】
直接给出建议的主标题、必要的一句话结论或副标题、模块标题、关键数字标签，以及简洁说明、风险或条件提示。文案应尽量可以直接放进PPT，简洁、可扫读、像给管理层看的文字，而不是给Agent看的结构化字段。

【P0 / P1 / P2 信息层级】
P0：第一眼必须看到的核心判断或核心数字。
P1：证明P0、解释主要关系的关键证据。
P2：必须保留但视觉上应弱化的辅助事实和细节。
明确哪些内容应放大、哪些弱化、哪些就近标注。

【关键数字视觉权重】
指出哪些数字属于Hero Metric、Primary Metric或Secondary Metric。不要让所有数字同样大小、同样醒目。

【视觉任务与建议表达】
先明确：“这个视觉必须让观众一眼看出：______。”
再根据内容真实关系推荐最合适的图表、时间关系、流程/关系图、对象比较、矩阵、表格、大数字、图片或简洁文字。推荐表达属于强设计建议，但不锁死具体图形样式。设计Agent如有更清楚、更美观的方案，可以调整表达方式，只要视觉任务和业务关系不被削弱。

【建议构图与阅读顺序】
说明页面主要区域分别承担什么作用、哪部分是视觉主体、哪部分是辅助证据、哪些内容必须靠近不能分开、大致视觉占比，以及推荐阅读顺序1→2→3。可以描述“上部/下部、左/右、主体约占一半”等，但不要写具体像素、绝对坐标或固定模板槽位。

【语义配色与可读性】
在母版基础上说明哪些属于正常/进展信息、风险或不确定性、重点结论及应弱化信息。颜色用于表达语义，不为丰富页面而增加颜色。关键文字和数字必须在16:9会议屏幕下清楚可读，不允许为了塞内容无限缩字。

【动画建议】
只有动画能帮助理解时间、流程、因果、并行等关系时才建议。说明出现顺序和认知目的，以Fade、Wipe、Appear等克制动画为主。如果没有必要，直接写“本页无需动画”。

【禁止事项】
针对本页指出最容易做错的地方，例如：不要机械做成等大卡片；不要把连续关系拆成互不相关模块；不要重复同一事实；不要把设计关键词直接打印到正文；不要为了填满页面增加无意义内容；不要把不确定信息表达成确定事实。

==================================================
三、设计Agent自由度
==================================================

以上页面指导是“强设计意图”，不是像素锁定。

后续PPT设计Agent可以根据真实排版调整具体区域比例、元素位置、图形形式、组件组合和空间分配，但不得改变或丢失：

1. 本页管理目标；
2. 5秒核心认知；
3. 全部重要且独有的业务事实；
4. P0/P1/P2信息层级；
5. 核心语义关系；
6. 关键数字视觉权重；
7. 内容边界；
8. 用户硬要求。

==================================================
四、最终输出
==================================================

只输出《PPT逐页制作Prompt》，不要制作PPT，不输出IR、JSON、Schema或分析过程。

【汇报名称/章节】
……

【受众与会议目的】
……

【原始材料】
……

【用户硬要求】
……

【PPT母版/品牌规范，如有】
……
```

## 三、制作页面：各负责人操作

```text
请使用 $mint-report-creative-ppt，根据附件原始材料和下面这份已确认的页面指导Prompt，制作原生可编辑PPT。

必须使用Skill内置的 mint-ppt-16x9-template.pptx（mint-template-16x9/1）作为原生母版；保留母版主题与PowerPoint自动页码。模板只规定字体、颜色、线条、间距和品牌层级，不限制内容布局。模板没有合适图形时，请按同一视觉语言自行组合原生可编辑图表、形状或关系图，不要退化为截图、普通表格或等大卡片。

先核对全部事实，再执行页面指导。推荐构图可以因真实排版采用明显更优方案，但不得改变页面目标、信息层级、视觉任务、关系和硬要求，并记录调整理由。全部业务信息进入可读正文，不放附录；底部除自动页码外不加非必要注释。完成来源、原生对象、母版/页码和独立视觉检查，不覆盖旧文件。

【我负责的章节】...
【已确认的页面指导Prompt】
...
```

如果使用任务卡，在开头补一句：

```text
读取附件 report.creative-task.json，只制作负责人【姓名】的章节；章节范围、顺序、来源和母版版本以任务卡为准。
```

## 四、优化调整

优先直接人工修改PPT。若需Agent修改：

```text
请使用 $mint-report-creative-ppt，以附件当前PPT为内容与页面顺序权威，只修改以下问题：【逐条列出】。
保留原生母版、自动页码、未点名页面的事实与关系，另存新文件。重新检查受影响页面及相邻页面，不读取旧IR恢复内容。
```

如果整体逻辑或构图方向错误，回到第二步重新生成并确认页面指导 Prompt，再执行第三步；不要用局部挪坐标掩盖结构问题。

## 合并与一致性

- 各负责人必须使用同一 Skill 版本、`mint-template-16x9/1`母版和同一报告受众/目的。
- 可在 Mac 或 Windows PowerPoint 中人工合并并选择“保留源格式”；不要求Agent合并。
- 合并后检查实际页序、自动页码、字体替换、重复内容、标题链以及图表/连接线。
- 任务卡减少范围与顺序差异；模板和品牌合同减少视觉差异。它们不会也不应强迫所有页面使用同一版式。
